# 文字与背景主题调整

本文描述应用自身的文字、背景和控件配色，不包含知乎图片、作者头像、正文自带色或第三方页面。

## 当前能力

“设置 → 外观与阅读”提供系统/浅色/深色模式、主色预设与自定义颜色、阅读背景、文字对比度、表面层次、未读角标样式，以及字号/行高设置。

未读角标用于关注动态头像、“我的 → 消息通知”和私信列表，可选红色数字（默认）、主题色数字、小圆点或不显示；样式由 `components/UnreadBadge.tsx` 统一渲染。

当前主色作为种子，由 Material Color Utilities 的 HCT 算法生成低彩度的中性色阶：背景、卡片、正文、边框和控件轻微带有主色色相，主色图标、短文字按钮和透明浅底保留原有配色，实心主色按钮也保留用户选定的原色。长提示文字与正文链接延续对主色做可读性调整的算法。危险、成功、警告保留自身颜色，不随主色变成其他含义。

这借鉴了 [Android 动态配色](https://developer.android.com/develop/ui/views/theming/dynamic-colors) 的种子色与色阶方法，但目前种子来自应用内设置，没有读取设备壁纸色；配色生成是跨平台的纯 JavaScript 实现。

## 阅读背景

阅读预设同时作用于页面、正文卡片和控件，不只是页面最外层。设置选项使用各档实际的正文背景与文字颜色作为小样，并说明作用。

| 显示名称 | 持久化 key | 作用 |
| --- | --- | --- |
| 随主题 | `default` | 清亮底色，低彩度地跟随主色 |
| 柔灰 | `soft` | 灰色表面降低明暗反差；暗色下适度抬高表面亮度 |
| 暖纸 | `warm` | 米色/棕灰的纸感底色与文字；只轻微向主色色相靠拢 |
| 低亮 | `dim` | 同时降低页面、卡片和控件亮度；暗色下更接近黑底 |

四个已有 key 与其他偏好字段不变，无需持久化迁移。默认主色重置直接使用静态品牌色，不能读取受当前用户设置影响的 `Colors.light.primary`。

## 对比度和表面层次

正文、次要文字、三级文字和链接对全部中性阅读表面至少保持 4.5:1；“高对比”进一步提高正文到至少 7:1。文字仍可带有少量主题色，不靠把所有文字改成纯黑或纯白实现层级。

“分层”让页面、卡片和控件保持不同明度，列表里的内容是一张张圆角卡片，卡片之间留间距、不加分割线；“扁平”同时统一卡片、控件和聊天气泡表面，列表内容（热榜、推荐与关注流、回答预览、个人创作）去掉卡片底色和圆角，相邻内容之间用分割线隔开。两种样式共用 `useContentCardSurface`，边框仍保留必要分隔。

实心主色按钮的 `onPrimary` 根据填充色的 HCT 明度动态选择黑或白：默认蓝色使用白字，亮黄、白色等亮色使用黑字，不随整体明暗模式、阅读背景或正文对比度设置变化。同一按钮的文字、图标和加载动画共用前景。该策略保留用户选择的原色，前景至少保持 3:1；默认蓝底白字约为 3.66:1，不属于上述正文 4.5:1 保证。`onDanger / onSuccess / onWarning` 仍按各自填充色选择最大黑白对比度。

浅色主色按钮继续使用现有主色加透明度，图标与短文字按钮继续保留原始强调色。这些配色以及照片、混合渐变与内容自带颜色不在上述文字对比度保证范围内。

## 代码与验证

统一入口、配对 token 和兼容别名见 [设计 Token](./DESIGN_TOKENS.md)。`runtimeTheme` 测试验证生成颜色及 React Native/Colors/NativeWind 同步；`appearanceSettings` 验证阅读预览、恢复默认与自定义色；`actionColorContrast` 验证投票和危险按钮的文字、图标及加载状态。

新增纯 JavaScript 依赖已锁定版本。未增加偏好字段、原生依赖或系统壁纸权限；升级配色库时需复核矩阵和实际页面观感。
